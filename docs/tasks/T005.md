- **Audited Components (VALID & OPERATIONAL):**
  - BoundingBox & VisualEvidence data contracts conforming strictly to `INTERFACES.md`.
  - Coordinate normalization, scaling (1000-scale and unit-scale), clamping, and parsing in `CoordinateParser`.
  - Full support for ShowUI-2B native output formats:
    - Grounding point coordinates: `[x, y]` (unit scale or 1000 scale)
    - Python action dictionaries: `{'action': 'CLICK', 'position': [0.73, 0.21]}`
    - Two-point selection boxes: `{'action': 'SELECT_TEXT', 'position': [[0.1, 0.2], [0.8, 0.9]]}`
    - Four-coordinate bounding boxes: `[ymin, xmin, ymax, xmax]` and `<box>...</box>` tags
  - Fail-closed screenshot input validation (`InvalidScreenshotError`).
  - Fail-closed error hierarchy (`VisualPerceptionError`, `InvalidScreenshotError`, `BackendAllocationError`, `ModelInferenceError`, `CoordinateParsingError`).
  - Offscreen document request/response message handling protocol.
  - Fail-closed model adapter with backend negotiation (WebGPU with WASM/CPU fallback).
- **ShowUI-2B Model Artifact & Runtime Investigation:**
  1. **Quantized Artifact Audit:**
     - Verified checkpoint: `localattention/ShowUI-2B-Q4_K_M-GGUF` (1.12 GB, converted from `showlab/ShowUI-2B`).
     - **CRITICAL FINDING:** `localattention/ShowUI-2B-Q4_K_M-GGUF` contains *only* the LLM weights (`showui-2b-q4_k_m.gguf`). It does *not* contain the multimodal vision projector (`mmproj`).
     - Processing screenshot image tokens requires pairing with `mmproj-Qwen2-VL-2B-Instruct-Q8_0.gguf` (~650 MB) from `ggml-org/Qwen2-VL-2B-Instruct-GGUF`.
  2. **Browser Runtime Reference (`pdufour/browser-use-wasm`):**
     - Employs `@wllama/wllama` (WASM + WebGPU) with OPFS/IndexedDB caching.
     - Demonstrates browser-side execution of ShowUI-2B Q4_K_M by pairing `showui-2b-q4_k_m.gguf` with `mmproj-Qwen2-VL-2B-Instruct-Q8_0.gguf`.
     - Output is formatted as Python navigation dictionary strings (`{'action': 'CLICK', 'position': [x, y]}`), which `CoordinateParser` now natively parses into `VisualEvidence`.
  3. **Architectural Conflict (ADR 005 vs Reality):**
     - Frozen architecture in `DECISIONS.md` (ADR 005) specifies: *ShowUI-2B executed locally via ONNX Runtime Web / WebGPU*.
     - However, no pre-existing official or community ShowUI-2B ONNX graph exists, whereas a verified GGUF artifact (`localattention/ShowUI-2B-Q4_K_M-GGUF`) and runtime engine (`@wllama/wllama`) exist.
     - Per `AI003.md` (§19, §20 Zero-Guessing Rule), AI003 cannot unilaterally replace ONNX Runtime Web with Wllama without an Architectural Decision Record (ADR) approved by the Lead Architect.
- **Shortest Technically Valid Path to Full Resolution:**
  1. **Architectural Decision (ADR):** Lead Architect approves ADR amending ADR 005 to permit `@wllama/wllama` (WASM/WebGPU) as an authorized execution runtime for ShowUI-2B alongside ONNX Runtime Web.
  2. **Dependency Declaration:** Add `@wllama/wllama` to `package.json` with appropriate CSP (`wasm-unsafe-eval`) and cross-origin isolation flags in `manifest.json`.
  3. **Asset Provisioning / Caching:** Offscreen document fetches and caches `showui-2b-q4_k_m.gguf` (1.12 GB) and `mmproj-Qwen2-VL-2B-Instruct-Q8_0.gguf` (650 MB) in IndexedDB/OPFS.
  4. **Adapter Execution:** `ShowUIAdapter` feeds raw screenshot buffer + `SHOWUI_GROUNDING_SYSTEM_PROMPT` to Wllama session and parses output directly via `CoordinateParser` into `VisualEvidence`.
