## 7. Escalation Report (AI004)
**Status:** BLOCKED

1. **Task ID and Step:**
   - Task ID: T006
   - Step: Implementation of M04 (DOM Evidence Extraction).

2. **Verification Against Authoritative Documents and T004 Implementation:**
   - The CDP type issue CAN be resolved purely locally in M04 by defining structural CDP schemas (e.g., in `src/m04-dom/cdp.ts`), as explicitly permitted by the instruction to use existing repository conventions.
   - The **Bounding Box extraction requirement**, however, remains a genuine architectural impossibility.
   - I have verified the actual T004 implementation in `src/m02-observation/domCapture.ts`: it explicitly executes `DOM.getDocument` and returns the bare `result.root`, which intrinsically contains no bounding box geometry.
   - I have verified `SYSTEM-DESIGN.md` and `MODULES.md` for M04: The exact inputs are restricted to `RawObservation.dom_tree` and `RawObservation.a11y_tree`, and the boundary explicitly mandates "Read-Only inspection of CDP trees passed from M02". Unlike M10, which explicitly lists `chrome.debugger` as a dependency to call `DOM.getBoxModel`, M04's dependencies are restricted purely to "CDP DOM and Accessibility schemas".
   - Because M04 is neither provided geometry by M02 nor permitted to use `chrome.debugger` to retrieve it independently, it is structurally impossible to fulfill the `INTERFACES.md` requirement to output `bbox: BoundingBox` in `DomEvidence`.

3. **Escalation:** Escalate to the Lead Architect for an ADR. Either M02 must capture geometry (e.g., via `DOMSnapshot.captureSnapshot`), or M04 must be granted explicit architectural permission and dependencies (i.e. `tabId` and `chrome.debugger`) to perform `DOM.getBoxModel` lookups.
